# פוסטים מחדשות הנדל״ן בשרון, ועיצוב מחדש של כל הפוסטים במנוע

## מה זה
שני תהליכים שרצים מחוץ לדפדפן, על אותו סטודיו שבמנוע (`public/engine/studio`):

1. **עיצוב מחדש בכמות.** `scripts/studio-batch.mjs` עובר על הפוסטים במנוע, בונה לכל אחד את שלושת הקונספטים של הסטודיו, ושומר את הטוב ביותר שעבר ביקורת (8.5 ומעלה) ב-`p.studio`. זו בדיוק הפעולה של "שמירה לפוסט" בסטודיו. העיצוב המקורי נשאר בפוסט, והמנוע מציג את העיצוב החדש בפורמט 4:5.
2. **פוסטים מחדשות.** קובץ `scripts/news-posts/<תאריך>.mjs` מחזיק פוסטים שנכתבו מכתבות אמיתיות. אותו סקריפט, עם `--news`, מעצב אותם ומכניס אותם למנוע כפוסטים חדשים בסטטוס "בבדיקה".

## כללי הפוסטים מחדשות
- כל מספר, תאריך ושם בפוסט מופיע בכתבה עצמה, שנפתחה ונקראה. תקציר של מנוע חיפוש לא מספיק.
- מקור ותאריך בסוף הטקסט ("המקור: מרכז הנדל״ן, 29.10.2026"), וגם בשדה `source` של הפוסט.
- מבדילים בין שלבים: הפקדה, אישור להפקדה, מתן תוקף. "אושרה להפקדה" הוא לא "אושרה".
- בלי תחזיות שלנו, בלי פוליטיקה ובלי אנשים פרטיים. תחזית של גוף רשמי (בנק ישראל) מותרת כשכתוב של מי היא.
- כתבות מ-60 הימים האחרונים בלבד. כתבה בלי תאריך לא נכנסת.
- קו המותג של הסוכן המעצב: בלי מקפים כסימן פיסוק, שאלה או קריאה לפעולה בסוף, חתימה והאשטגים.
- כל פוסט מסביר למה זה חשוב למי שבונה בית פרטי, קונה, מוכר או מחזיק קרקע בשרון.
- אתרים שנגישים מסביבת העבודה: nadlancenter.co.il, bizportal.co.il, ice.co.il, cbs.gov.il, boi.org.il. funder ו-calcalist חוסמים בקשות אוטומטיות.

## הרשאה
הסקריפט מדבר עם פונקציית ה-Edge `studio-batch`. היא מקבלת טוקן חד פעמי: ה-sha256 שלו נשמר בטבלה `studio_batch_tokens` עם תוקף, ונמחק בסוף הריצה. בריפו אין שום מפתח.

```bash
openssl rand -hex 32 > /tmp/batch.token
printf %s "$(cat /tmp/batch.token)" | sha256sum   # את ה-hash מכניסים:
# insert into public.studio_batch_tokens(hash, expires, note) values ('<hash>', now() + interval '2 hours', 'news <date>');
node scripts/studio-batch.mjs --news scripts/news-posts/<date>.mjs --photos <photos.json> --out /tmp/news --batch news<date> --token-file /tmp/batch.token
# delete from public.studio_batch_tokens where hash = '<hash>';
```

את `photos.json` מורידים דרך הפונקציה: `POST {"op":"list","collection":"photos","size":1000}` עם הכותרת `x-batch-token`. בלי `--token-file` שום דבר לא נכתב: העיצובים נשמרים כקבצי webp בתיקיית `--out` לבדיקה.

## ביטול
כל עיצוב שנשמר בכמות מסומן ב-`auto`. ביטול של ריצה שלמה:

```sql
update engine_docs set data = data #- '{p,studio}' where collection = 'posts' and data->'p'->'studio'->>'auto' = 'b20261114';
```

ופוסטים מחדשות שלא אושרו נמחקים מהמנוע כמו כל פוסט.

## מה הסטודיו לא בוחר בריצה בכמות
- **קרוסלה מלמדת** (6 שקפים) נבחרת רק לפוסט שהוא קרוסלה. בפוסט של תמונה אחת השער היה כותב "החליקו", ואחריו לא היה כלום.
- **לפני ואחרי** נבחר רק כששתי התמונות מתויגות באותו פרויקט.
- **מגורים** ו**צילום מלא** נבחרים רק עם צילום אמיתי, לא עם איור או גרפיקה של המותג.
- **פוסטים של רילס, וידאו וסטורי** לא מקבלים עיצוב: הקאבר שלהם הוא פריים מהסרטון.
