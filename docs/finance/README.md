# KURKOOS FINANCE AI

מערכת פנימית של קבוצת קורקוס לאיסוף חשבוניות וקבלות, בקרה, אישור וייצוא לרואה החשבון.
כתובת: `/admin/finance`. קישור גם מתפריט ניהול האתר: מערכת › הנהלת חשבונות.

## ארכיטקטורה

הכול בנוי על התשתית הקיימת של האתר, בלי שירות חדש:

| שכבה | מה | איפה |
|---|---|---|
| ממשק | React + Vite, RTL, מותג קורקוס (Almoni / Heebo, נייבי, אדום) | `src/pages/finance/` |
| שרת | פונקציית Vercel אחת (`api/[fn].js` › `server/finance.js`) | `server/finance/` |
| מסד נתונים | Postgres של Supabase, הרשאות ב-RLS | `supabase/finance.sql` |
| קבצים | דלי פרטי `finance-docs` ב-Supabase Storage | |
| התחברות | Supabase Auth (אותה כניסה של ניהול האתר) + תפקידים בטבלה `fin_members` | |
| תזמון | Vercel Cron פעם ביום (`/api/finance?action=cron`) | `vercel.json` |
| AI | Claude (`claude-opus-5-5`, פלט מובנה לפי סכמה) | `server/finance/extract.js` |
| מייל | Gmail API ו-Microsoft Graph, OAuth בהרשאת קריאה בלבד | `server/finance/providers/` |
| WhatsApp | Green API: webhook נכנס ותשובה לשולח | `server/finance/whatsapp.js` |
| ענן | Google Drive (`drive.file`) ו-Dropbox, העתקת מסמכים מאושרים | `server/finance/cloud.js` |

### מודולי השרת (הסוכנים)

| קובץ | סוכן | תפקיד |
|---|---|---|
| `providers/gmail.js`, `providers/outlook.js` | 1. סריקת מייל | חיפוש מיילים כספיים, גם כשהנושא לא אומר "חשבונית" (כל מייל עם PDF מצורף נבדק) |
| `pipeline.js › syncMailbox` | 2. איסוף מסמכים | הורדה, טביעת SHA-256, מניעת כפילויות, שמירת המקור והמייל |
| `extract.js` | 3+4. סיווג וקריאה | Claude מחזיר סוג מסמך, שדות וודאות לכל שדה. אסור לו לנחש: שדה שלא מודפס נשאר ריק |
| `validate.js` | 5. בקרה | חשבון (לפני מע״מ + מע״מ = סה״כ), שיעור מע״מ, ספרת ביקורת של ח.פ, שדות חובה, כפילויות, סכום חריג, תאריך עתידי, ודאות נמוכה. בלי AI |
| `assign.js` | 6. שיוך | חברה, פרויקט וקטגוריה לפי: כללים › ברירות מחדל של הספק › היסטוריית אישורים › ח.פ הלקוח במסמך › התיבה. פרויקט נקבע רק כשזה ודאי, אחרת הוא הצעה |
| `agents.js` | 7. סיכום יומי + אוטומציות | הריצה היומית, ניסיונות חוזרים, התראות, סיכום במייל (Resend) |
| `adapters.js` | ייצוא | ממשק אחיד לתוכנות הנהלת חשבונות. קבצים עובדים תמיד; API מופעל רק אחרי אישור רו״ח ומפתח |

### מסד הנתונים (`supabase/finance.sql`)

`fin_businesses` (חברות) · `fin_projects` · `fin_members` (משתמשים ותפקידים) · `fin_suppliers` · `fin_categories` (עם % קיזוז מע״מ) ·
`fin_documents` · `fin_mailboxes` + `fin_mailbox_secrets` (טוקנים, שרת בלבד) · `fin_mail_seen` · `fin_rules` · `fin_automations` ·
`fin_agent_runs` · `fin_sync_runs` · `fin_summaries` · `fin_exports` · `fin_integrations` + `fin_integration_secrets` · `fin_audit` ·
`fin_whatsapp_senders` + `fin_whatsapp_inbox` · `fin_cloud_targets` + `fin_cloud_secrets` (שרת בלבד) + `fin_cloud_synced` ·
`fin_outbound` + `fin_outbound_secrets` (שרת בלבד) + `fin_outbound_queue` · `fin_oauth_used`.

כללי ברזל שנאכפים במסד עצמו (לא רק במסכים):
- שום מסמך לא נולד מאושר. רק מנהל מערכת או מנהל כספים מאשרים.
- מסמך מאושר או שיוצא: השרת וה-AI לא יכולים לשנות אותו. אדם שמשנה סכום, ספק או שיוך מחזיר אותו לבדיקה.
- ייצוא רק דרך `fin_record_export`: בודקת תפקיד, שכל המסמכים מאושרים, ושלא יוצאו כבר (אלא אם מבקשים ייצוא חוזר במפורש).
- כל יצירה, תיקון (עם ערך לפני ואחרי), אישור, דחייה, ייצוא ומחיקה נרשמים ב-`fin_audit` עם המשתמש.
- קובץ נקרא רק דרך מסמך שמותר לקרוא. אין קישורים ציבוריים.
- משתמש שאינו מנהל מערכת (רו״ח, עובד, מנהל כספים) לא יכול לכתוב בטבלאות האתר ולא לקרוא טבלאות פרטיות כמו לידים (מדיניות RESTRICTIVE). גם שער ה-API חוסם אותו מכל נתיבי האתר.

## נתוני יסוד וניהול חכם (גרסה 3)

- **ארבע ישויות מחוברות** (חברות, פרויקטים, ספקים, קטגוריות) עם מפתחות זרים: ארגון ← חברה ← פרויקט ← מסמכים. לכל ישות יש רשימה עם חיפוש וסינון, טופס עם בדיקת ח.פ ובדיקת כפילויות, ארכיון (ישות עם מסמכים לא נמחקת), ייבוא וייצוא CSV, ועמוד פיננסי (תקופה, סיכום, מגמת 12 חודשים, פילוחים, מסמכים, היסטוריה, תקציב מול ביצוע).
- **זיהוי ספק בכל מסמך**: לפי ח.פ, שם מנורמל (`fin_norm`, אותו מנרמל בשרת ובמסד), דומיין ואתר. ספק לא מוכר: במצב **מבוקר** נוצרת הצעה שממתינה לאישור, ובמצב **אוטומטי** הוא נוצר אם יש ח.פ, הוודאות מעל הסף ואין כפילות. אפשר לאחד ספקים כפולים.
- **שיוך עם ודאות וספים** (הגדרות › זיהוי ושיוך אוטומטי). ח.פ הנמען המודפס גובר תמיד. ספק שעובד בכמה פרויקטים לא קובע פרויקט לפי שמו. סתירה בין שני סימנים ודאיים מסומנת לבדיקה.
- **מנוע כללים**: 11 סוגים, עדיפות, הפעלה וכיבוי, היסטוריית הפעלות (`fin_rule_hits`: הוחל / הוצע / נדחה / סומן), מי שינה לאחרונה, ויומן. רק מנהל מערכת משנה כללים.
- **פיצול חשבונית בין פרויקטים** (`fin_document_allocations`, ‏`fin_set_allocations`): הפיצול תמיד מתאזן לסה״כ, והמקור לא משתנה.
- **אישור כפול** מעל סכום שמנהל קובע: נאכף במסד. הדגל מחושב שם, ואי אפשר לכבות אותו או לזייף חתימה ראשונה דרך ה-API.
- **מרכז בקרה**: חברות, פרויקטים, ספקים, בקרת מסמכים, ופעולות ה-AI. הדיוק של הסוכנים נמדד מול מה שאנשים אישרו (`ai_snapshot` מול הערך הסופי).
- **כרטיסי מסמכים** עם תמונה ממוזערת של העמוד הראשון (pdf.js, נטען רק כשצריך), ופעולות מהירות.
- **חיפוש גלובלי**: ‎Ctrl/⌘+K או `/`.

## חיבורים: אימייל, סורקים ניידים וענן (גרסה 4)

- **חשבונות אימייל**: כרטיס לכל תיבה (ספק, חברה משויכת או "אין עסק", סנכרון אחרון, מצב, תפריט פעולות), "סנכרון כל החשבונות עכשיו", והוספת Gmail או Office 365.
  תיבה חדשה נסרקת 90 יום אחורה. **קבלות ישנות** קובע תאריך מוקדם יותר (עד 4 שנים) וסורק רק את הטווח החדש. מיילים שכבר נקראו לא נקראים שוב (`fin_mail_seen`).
- **סורקים ניידים (WhatsApp)**: רושמים מספר נייד (עם שם, חברה ומשתמש). צילום או PDF שנשלח מהמספר הזה למספר של המשרד נכנס כמסמך לבדיקה, נקרא ב-AI, והשולח מקבל אישור עם הספק והסכום.
  מספר לא רשום, קבוצה, הודעה כפולה וקובץ שכבר קיים מטופלים בנפרד, וכל הודעה נרשמת ב"הודעות אחרונות".
  **מספר שלא רשום כסורק לא מקבל שום הודעה מהמערכת, לעולם** (זה גם הקו שלקוחות ולידים כותבים אליו), וגם הודעת טקסט רגילה ממספר רשום לא נענית: רק מי ששלח קובץ ממספר רשום מקבל תשובה.
- **סנכרון לענן**: Google Drive ו-Dropbox. מסמכים מאושרים ומיוצאים מועתקים לתיקייה (ברירת מחדל `Kurkoos Finance/<חברה>/<חודש>`), פעם ביום ובלחיצה. כל מסמך מועתק פעם אחת בלבד לכל יעד.
  ל-Drive ההרשאה היא `drive.file`: המערכת רואה רק את הקבצים שהיא יצרה.

## תוכנת הנהלת חשבונות, שליחה אוטומטית וארגון (גרסה 5)

- **חיבור תוכנת הנהלת החשבונות**: כרטיס לכל תוכנה (Morning, iCount, רווחית, SUMIT, Paperless, Priority, חשבשבת, קבצים) עם חיפוש. לכל חברה אפשר לחבר תוכנה אחת (נאכף בשרת ובאינדקס במסד).
  המפתחות נשמרים ב-`fin_integration_secrets` (שרת בלבד). השליחה הישירה ב-API עדיין לא מופעלת: התוכנה מסומנת "ממתין להפעלה", והמסמכים יוצאים בקבצים עם אישור.
- **שליחה אוטומטית** (`server/finance/outbound.js`): webhook או כתובת מייל מקבלים אירועים: מסמך נקלט, אושר, נדחה, יוצא לרו״ח.
  טריגר על `fin_documents` כותב לתור `fin_outbound_queue`, והשרת שולח מיד אחרי הפעולה (ובריצה היומית). ניסיונות חוזרים אחרי 1, 5, 30 דקות, שעתיים ו-12 שעות.
  ה-webhook חתום: `X-Kurkoos-Signature: t=<unix>,v1=<HMAC-SHA256 של "t.body">`. הסוד מוצג פעם אחת ונשמר ב-`fin_outbound_secrets`. רק `https`, ולא לכתובות ברשת פנימית.
  המייל נשלח דרך Resend עם הקובץ המקורי מצורף (עד 10MB, אחרת קישור בתוקף 24 שעות). כל אירוע נשלח פעם אחת לכל מסמך: מסמך שאושר, הוחזר לבדיקה ואושר שוב לא נשלח פעם שנייה.
- **הארגון ומשתמשים**: לשוניות חברי ארגון (חיפוש, סינון לפי תפקיד, מיון, הזמנות שממתינות להצטרפות ושליחה חוזרת), חברות, ושימוש (אחסון, מסמכים וקריאות AI החודש).
- **תיקונים מסקירת הקוד**: קליטת WhatsApp נעצרת ב-75% אחסון, מורידה קבצים רק משרתי Green API עם הגבלת גודל וזמן, ומזהה הודעה כפולה גם כשהראשונה עוד בעיבוד.
  סנכרון הענן מסנן ב-SQL (בלי תקרה של 500), מדלג על מסמך תקול במקום להיתקע, ונועל יעד כדי שהריצה היומית והכפתור לא יכפילו קבצים.
  OAuth: ה-state חד-פעמי והתפקיד נבדק שוב בחזרה. "קבלות ישנות" סורקת רק את הפער בין התאריכים, כך שגם תיבה עמוסה מגיעה למיילים הישנים.

## צוות, תפריט מובייל וחיזוק השליחה (גרסה 6)

- **הזמנת רו״ח או חבר צוות**: כשבארגון רק המנהל מוצג מסך הזמנה עם מדריך שלב אחרי שלב. בטופס בוחרים תפקיד מכרטיסים (ברירת מחדל: רו״ח), ואפשר להגביל לחברות.
- **תפריט מובייל**: בראש התפריט המשתמש וכפתור סגירה, וכרטיס "קבוצת קורקוס". "חשבונות אימייל" ו"סורקים ניידים" עברו לקבוצה "מקורות".
  בסרגל העליון כפתור "קבלות ישנות" שפותח ישר את חלון הסריקה הרטרואקטיבית.
- **חיזוק השליחה האוטומטית**: הכתובת נבדקת ברגע החיבור עצמו, כך ששם שמצביע אחר כך לרשת פנימית (DNS rebinding) נחסם. נחסמות גם כתובות IPv6 שמכילות IPv4 פנימי.
  הניסיון נספר כבר ברגע שהמשלוח נלקח, כך שמשלוח שמפיל את הפונקציה לא חוזר לנצח. יעד מושהה שומר את המשלוחים שלו, והמונים מתעדכנים בפקודה אחת.
  קישור לקובץ בתוקף 24 שעות. אפשר להשהות webhook גם כשהשרת שלו כבר לא קיים.
- **WhatsApp**: הודעה שהעיבוד שלה נקטע (מגבלת 60 שניות) נקלטת מחדש בניסיון החוזר של Green API אחרי 3 דקות.
- **תוכנה אחת לכל חברה** כולל "כל החברות": חיבור לכל החברות חוסם חיבור לחברה מסוימת, ולהפך.

## עיצוב אחיד ושליחה לרו״ח (גרסה 7)

- **רכיבים משותפים**: רשימה נפתחת אחת לכל המערכת (`Select.jsx`: חיפוש, מקלדת, נשארת בתוך המסך, גיליון תחתון בטלפון, ה-select המקורי נשאר מתחת לנגישות ולטפסים),
  תפריט ⋮ צף, חלונות עם פוקוס כלוא, טוקנים של מרווחים, טיפוגרפיה, גבהים ותנועה, תפריט צד מתכווץ, ותצוגת מסמך שמציירת את כל עמודי ה-PDF עם זום.
- **סינון לפי טווח תאריכים** (`DateRange.jsx`): לוח של שני חודשים (חודש אחד כגיליון בטלפון), לפי תאריך המסמך או תאריך הקליטה, וטווחים מהירים.
- **שליחה לרו״ח** (`server/finance/mailout.js`): המסמכים שבטווח, או המסומנים, נשלחים במייל אחד עם הקבצים המקוריים וקובץ CSV לקליטה.
  עד 25MB מצורפים, והשאר נשלחים כקישורים בתוקף 7 ימים. רק מנהל מערכת ומנהל כספים יכולים לשלוח, ורק מסמכים של החברות שלהם. אפשר לסמן את המאושרים כ"יוצא לרו״ח".
- **בדיקה ויזואלית**: `scripts/finance-e2e/visual-qa.mjs` + `qa-report.mjs` › `docs/finance/VISUAL-QA.md`.

## מוצר פשוט סביב תהליך אחד (גרסה 8)

המערכת בנויה סביב תהליך אחד: לאסוף חשבוניות אוטומטית (מייל, WhatsApp, העלאה), לקרוא אותן (OCR ו-AI), לבדוק, ולשלוח לרו״ח.

- **ניווט**: "מסמכים" (מרכז בקרה, כל המסמכים, חדשות, לבדיקה, שליחה לרו״ח, היסטוריית ייצוא), "נתוני יסוד", "קליטה" (חיבורים, אימייל, סורקים ניידים), וכל השאר מקופל תחת "מתקדם".
- **מרכז בקרה**: שתי פעולות (העלאת מסמך, שליחה בוואטסאפ), ארבעה מספרים (חדשים, לבדיקה, מוכנים לרו״ח, נשלחו החודש), שורת התראה כשמסמך לא נקרא או חשוד ככפול, מסמכים אחרונים ומצב האיסוף (תיבות, WhatsApp, סריקה אחרונה והבאה, נאספו היום).
  הניתוח הכספי (הוצאות לפי חברה, פרויקט, ספק ודיוק ה-AI) עבר ל"דוחות › תמונת מצב".
- **סטטוסים**: בעיבוד · לבדיקה · מוכן לרו״ח · נשלח לרו״ח · לא נקרא · חשד לכפילות · נדחה.
- **שליחה לרו״ח** (`SendCenter.jsx`): המסמכים המוכנים, סינון לפי תאריך, חברה ופרויקט, ביטול מסמכים בודדים, וסרגל סיכום (מסמכים, סכום, חברות, תקופה, לא אושרו).
  המסמכים המאושרים מסומנים "נשלח לרו״ח" רק אחרי ששרת הדואר קיבל את ההודעה והחזיר מזהה. כל שליחה, גם שנכשלה, נשמרת ב-`fin_deliveries`.
- **תצוגת מסמך**: זום, התאמה לרוחב, התאמה למסך, מסך מלא, הורדת המקור, הדפסה ושיתוף.
  שיתוף בטלפון פותח את חלון השיתוף של המכשיר עם הקובץ עצמו. מכל מכשיר אפשר לשלוח את הקובץ מה-WhatsApp של המשרד דרך Green API (`sendFileByUrl`).
  עובד שולח רק מסמכים שלו ורק לטלפון רשום, והשיתוף נרשם ביומן.
- **אישור ב-WhatsApp**: "החשבונית התקבלה ונקלטה במערכת בהצלחה" עם ספק, סכום, חברה וקישור למסמך (`SITE_URL`). אם הקריאה לא הצליחה, השולח מקבל הודעה שהמסמך ממתין לבדיקה ידנית.
- **חיבורים** (`Connections.jsx`): כל המקורות והיעדים ברשימה אחת, עם מצב ופעילות אחרונה. אם בדיקת המצב לא ענתה, מוצג "לא ידוע" ולא "לא מוגדר".
- **רענון**: הנתונים מתרעננים כשחוזרים ללשונית, וכשעוברים מסך אחרי יותר מ-20 שניות, כדי שעבודה של אנשים אחרים תופיע.

## מנוע האיסוף (גרסה 9)

כל מסמך, מכל מקור (מייל, WhatsApp, העלאה, צילום), עובר באותו מסלול: שמירת המקור › קריאה (Claude: OCR, פריסה וסיווג בעברית ובאנגלית) › בדיקות › זיהוי ספק, חברה, פרויקט וקטגוריה › כפילויות › רשומה במסד.

- **שכבות אימות**:
  1. **איכות התמונה**: קריא, מטושטש, חתוך, הפוך, חסר עמוד, כתב יד.
  2. **חשבון**: לפני מע״מ ועוד מע״מ שווה לסה״כ, שיעור מע״מ, ספרת ביקורת של ח.פ, תאריך.
  3. **קריאה שנייה ממוקדת** (`verify`, יותר מאמץ) של ח.פ, מספר, תאריך וסכומים. רצה רק כשהקריאה לא בטוחה, כשהחשבון לא נסגר או כשהתמונה חלשה. כשהשתיים מסכימות הוודאות עולה. כשהן לא מסכימות, שני הערכים נשמרים (`extraction.verification`) והשדה מסומן לבדיקה.
  4. **ודאות לכל שדה בנפרד.**
- **כפילויות**: אותו קובץ (טביעה) לא נשמר פעמיים. אותו ח.פ ומספר מסמך, מכל מקור, נסגר ככפול ומקושר למקור (`duplicate_of`).
  אותו ספק, סכום ותאריך (±יום) נשאר לבדיקה כ"חשד לכפילות" עם קישור למקור, רק כשלקבלה החדשה אין מספר או שהמספר זהה. שתי קבלות עם מספרים שונים הן שתי קניות. אדם מחליט: "זה כפול" או "לא כפול", ו"לא כפול" לא חוזר בקריאה הבאה.
- **אמינות**: כל קריאה תופסת את המסמך (`fin_doc_claim`), כך ששתי ריצות לא קוראות אותו מסמך ולא משלמות פעמיים. הניסיון נספר כבר בתחילת הקריאה.
  קריאה שנכשלה מנוסה שוב בסריקת הלילה הבאה, עד 3 פעמים ברצף, ואז נעצרת לטיפול ידני ("קריאה מחדש עכשיו" במסך המסמך).
  מסמך שנתקע "בעיבוד" יותר מ-10 דקות (פונקציה שנפלה) נקרא מחדש. הקובץ המקורי נשמר תמיד, ושום מסמך לא נעלם.
- **תזמון וחיסכון**: סריקה אחת בלילה, ב-00:23 UTC (02:23 בחורף, 03:23 בקיץ). זו הריצה היחידה שאוספת מיילים ומנסה שוב מסמכים שנכשלו.
  דוח הבוקר (04:57 UTC, כלומר 06:57 בחורף ו-07:57 בקיץ) קורא רק מהמסד, בלי AI.
  פתיחת המערכת לא מפעילה שום סריקה. AI נקרא במהלך היום רק כשאדם שולח מסמך: העלאה, צילום, WhatsApp או "קריאה מחדש".
  כפתורי "סנכרון עכשיו" ו"קבלות ישנות" נשארו, ורצים רק כשלוחצים עליהם.
- **קריאה שנייה רק כשצריך**: רק כשהחשבון לא נסגר, כשהתמונה מטושטשת או חתוכה, או כשהוודאות של הסה״כ או המע״מ מתחת ל-70%. היא רצה ברמת מאמץ בינונית.
- **צילום קבלה**: התמונה מסובבת לפי ה-EXIF ומוקטנת במכשיר ל-2200 פיקסלים JPEG לפני ההעלאה. היא נקראת מיד, ומוצגים הספק, המספר, התאריך, הסכומים, אזהרות האיכות ותוצאת הקריאה השנייה, עם שיוך מהיר לחברה, לפרויקט ולקטגוריה.
- **מעקב עלות**: לכל מסמך נשמרים הקריאות והטוקנים (`ai_calls`, `ai_tokens_in/out`). מסך "סוכני AI" מציג את הסך החודשי (טוקנים, לא מחיר משוער), ו"פעיל" רק לסוכן שעבד באמת לאחרונה.
- **לא נבנה**:
  - פיצול PDF אחד עם כמה חשבוניות למסמכים נפרדים.
  - סנכרון מצטבר של Gmail history או Graph delta: הסריקה מבוססת זמן, עם רשימת מיילים שנקראו (`fin_mail_seen`).
  - עמודות המנוע (`stage`, `duplicate_state`, `ai_tokens`…) לא מוגנות ברמת המסד מפני עובד שעורך מסמך שלו (כמו `issues` היום).

## Excel, Google Drive, סיווג ושיתוף (גרסה 10)

- **Excel ו-CSV למסמכים מסומנים**: בסרגל הבחירה במסך המסמכים ("Excel", "CSV"), בדוח החודשי, בדוחות ובמייל לרו״ח.
  קובץ `.xlsx` אמיתי שנבנה בדפדפן ובשרת מאותו מודול (`src/pages/finance/expenseReport.js` + `xlsx.js`, בלי ספרייה):
  גיליון מימין לשמאל, שורת כותרת קפואה עם סינון, תאריכים כתאריך, סכומים כמספר בפורמט `#,##0.00`, זיכוי במינוס, שורת סה״כ,
  וגיליונות "לפי קטגוריה" (כולל אחוז מההוצאות) ו"לפי ספק". ה-CSV ב-UTF-8 עם BOM, תאריך dd/mm/yyyy ושורת סה״כ.
  16 עמודות: תאריך, ספק, ח.פ, סוג, מספר, חברה, פרויקט, קטגוריה, לפני מע״מ, מע״מ, סה״כ, מטבע, אמצעי תשלום, מקור, סטטוס, קישור בדרייב.
- **Google Drive לפי שנה וחודש**: ברירת המחדל לתיקייה חדשה היא `<תיקייה>/<שנה>/<מספר חודש> <שם החודש>`, לפי התאריך שעל המסמך
  (`Kurkoos Finance/2026/11 נובמבר`). שם הקובץ: `תאריך_ספק_סוג_מספר`. לפני העלאה נבדק אם יש כבר קובץ באותו שם באותה תיקייה,
  והוא לא מועלה שוב (גם ב-Dropbox: `autorename: false`). לכל עותק נשמר קישור (`fin_cloud_synced.web_link`), והוא מוצג בעמודה "ענן",
  בקובץ ה-Excel ובמייל. תיקייה שכבר העתיקה קבצים בסידור הישן נשארת בו; אפשר לשנות בהגדרות התיקייה.
- **שמירה בדרייב ידנית**: מסרגל הבחירה ומתצוגת המסמך (`cloud-save`), גם למסמך שעוד לא אושר. התשובה היא לכל קובץ בנפרד,
  וההודעה מספרת רק מה שנשמר באמת (נשמר / כבר היה / נכשל ולמה).
- **בדיקת חיבור אמיתית** (`cloud-test`, במסך "סנכרון לענן"): רענון הטוקן, יצירת התיקייה `בדיקת חיבור`, העלאת קובץ טקסט קטן,
  קריאה חוזרת שלו מה-API (`files.get` / `get_metadata`), ושמירת התוצאה והקישור. כשלון מסמן את החיבור "תקלה" ונרשם ביומן.
- **הבחנה בין חשבוניות למסמכים אחרים**: Claude מחזיר `document_class` ו-`relevance_confidence`. נשמרים: חשבונית מס,
  חשבונית מס/קבלה, קבלה, חשבון עסקה, זיכוי, דרישת תשלום, אישור תשלום. מדולגים: הצעת מחיר, הזמנה, חוזה, מסמך משפטי, פרסום,
  התכתבות, דף חשבון, אישי, אחר. מסמך מהמייל מדולג רק כשהסיווג בטוח (0.8 ומעלה) והוא לא מסמך כספי: אין לו רשומה כספית, רק שורה
  ב-`fin_skipped` (יומן פעילות › קבצים שדולגו), והקובץ לא נקרא שוב. סיווג לא בטוח נשמר כמסמך לבדיקה עם האזהרה
  "לא בטוח שזה מסמך הוצאה". מסמך שאדם העלה או צילם לא נמחק אף פעם: הוא נשמר עם אזהרה.
- **שיתוף**: חלון אחד למסמך אחד או לכמה: WhatsApp מהמספר של המשרד (קובץ לכל מסמך, עד 20) או מייל לכל כתובת (`email-docs`):
  הקבצים, Excel ו-CSV, בלי לסמן "נשלח לרו״ח".
- **דוח חודשי לרו״ח** (מסך "שליחה לרו״ח"): בוחרים חודש, רואים מסמכים, לפני מע״מ, מע״מ, סה״כ ו-5 הקטגוריות הגדולות,
  מורידים תצוגה מקדימה ב-Excel ושולחים. המייל לרו״ח הקבוע (הגדרות › "המייל הקבוע של רואה החשבון") או של החברה.
- **תצוגת המסמך**: מעבר בין עמודים (עמוד X/N), סיבוב ב-90° (תצוגה בלבד, הקובץ לא משתנה), שמירה בדרייב ושיתוף במייל.
- **מרכז הבקרה**: הוצאות החודש, מע״מ, השינוי מהחודש הקודם, מתחילת השנה, הספק והקטגוריה הגדולים וגרף של שישה חודשים.
- **יומן פעילות** (`/activity`): כל הפעולות עם מי ומתי, כולל ייצוא ב-Excel/CSV והורדות (`fin_log`, רק פעולות מותרות, המשתמש
  נלקח מהחיבור) ושגיאות של הסוכנים. סינון לפי סוג ולפי משתמש.

## קבוצת חברות, סקירה למנכ״ל ועוזר פיננסי (גרסה 11)

- **חברות**: מוסיפים, עורכים ומשביתים חברות במסך "חברות" (שם, ח.פ, שם מסחרי, כתובת, טלפון, מייל, רו״ח), בלי שינוי בקוד.
  חברה מושבתת נשארת עם כל המסמכים שלה.
- **שיוך מסמך לחברה, בשלוש רמות** (`server/finance/assign.js`):
  - **ודאי** (0.95 ומעלה, למשל ח.פ הנמען מודפס במסמך): משויך אוטומטית, `business_source = auto`.
  - **סביר** (0.85 ומעלה, למשל שם הנמען תואם לחברה בדיוק, או שני מקורות בלתי תלויים מסכימים): משויך ומסומן "בדקו שהיא נכונה"
    (`auto_likely`).
  - **לא ודאי**: לא משויך. המסמך מחכה בלשונית "ממתין לשיוך" עם הצעה, ומופיע ב"דורש תשומת לב".
  מקורות: ח.פ הנמען, שם הנמען (גם שם מסחרי ושם באנגלית), כתובת הנמען, כללים, תיבת המייל, והחברה של מסמכים קודמים מאותו ספק.
  **ספק לבד לא משייך**: היסטוריית הספק, ברירת המחדל שלו או תיבת המייל מגיעים לכל היותר ל-0.84, אלא אם מקור נוסף מסכים.
- **למידה מתיקון**: כשאדם בוחר חברה (במסמך או בסרגל הבחירה) המסמך מסומן `business_source = manual`. המסמך הבא של אותו ספק
  מקבל את החברה כהצעה. כל תיקון נרשם ביומן עם מי ומתי.
- **כללי ספירה** (`src/pages/finance/ledger.js`): קבלה או אישור תשלום שמשלמים חשבונית שכבר במערכת (אותו ספק, אותו סכום ±1 ₪,
  עד 180 ימים אחרי החשבונית) הם אישור תשלום ולא הוצאה נוספת. חשבון עסקה שאחריו הגיעה חשבונית מס על אותו סכום לא נספר.
  "שולם" מוצג רק כשיש מסמך שמאשר תשלום. סימון ידני מוצג בנפרד ("סומן כשולם ידנית"). כל המסכים, הדוחות והעוזר משתמשים באותם כללים.
- **סקירה פיננסית** (דף הבית של מנהל המערכת ומנהל הכספים; `Executive.jsx` + `insights.js`): הוצאות בתקופה מול התקופה הקודמת,
  מתחילת השנה מול השנה שעברה, מסמכים שנאספו, חשבוניות, קבלות (כמה מהן אישורי תשלום), מע״מ תשומות (ומה לקיזוז לפי הקטגוריות),
  חשבוניות בלי אישור תשלום, וממתינים לבדיקה. בנוסף: גרף 12 חודשים מול השנה הקודמת (בטלפון: רשימה של 6 חודשים), השוואת חברות,
  לאן הכסף הולך (קטגוריות באחוזים), ספקים מרכזיים, פרויקטים (תקציב מול ביצוע, עם התראה בחריגה ומעל 85%), "דורש תשומת לב"
  ואמינות הנתונים (כמה אושרו, כמה חולצו וממתינים, כמה לא נקראו). כל מספר נפתח לרשימת המסמכים שמרכיבים אותו.
  "מרכז בקרה" (העבודה היומית) עבר ל-`/today`. לעובדים ולרו״ח דף הבית נשאר כמו שהיה.
- **שאלות על הנתונים** (`/assistant`, `server/finance/assistant.js`): Claude רק מתרגם את השאלה לשאילתה (מה למדוד, תקופה,
  חברה, פרויקט, קטגוריה, ספק). השרת מחשב את המספר מהמסד באותו קוד של הסקירה. כל תשובה מציגה מספר, תקופה, היקף, הסבר
  ואת המסמכים שבחישוב. שאלה שאינה על הנתונים מקבלת "לא הבנתי" ולא מספר. משתמש שמורשה לחברה אחת מקבל תשובות רק עליה.
- **טלפון**: סרגל תחתון (סקירה, מסמכים, צילום קבלה, דוחות, עוד) עם אזור בטוח ל-iPhone. כל המסכים נבדקו ב-9 רוחבים.
- **ביצועים**: ראו `docs/finance/PERFORMANCE.md` (מדידה לפני ואחרי, 10,000 ו-50,000 מסמכים).
- **לא נבנה בגרסה הזו**:
  - תפקיד "מנהל פרויקט" (הרשאה לפי פרויקט). ההרשאות הן לפי חברה (`business_ids`) ולפי תפקיד.
  - חישוב הסיכומים בשרת. ראו PERFORMANCE.md.
  - שמירת סינונים מועדפים, ודוחות PDF שנוצרים בשרת: ה-PDF הוא דוח להדפסה מהדפדפן.

## אבטחת הכניסה ועיצוב לפי כללי UX (גרסה 12)

- **אימות דו-שלבי (TOTP)**: קוד מאפליקציית אימות (Google Authenticator, Microsoft Authenticator, 1Password). חובה לתפקידים
  שמוגדרים ב-`fin_settings.mfa_required_roles` (ברירת מחדל: מנהל מערכת ומנהל כספים; שינוי בשורה אחת, בלי קוד). לתפקיד כזה,
  אחרי הסיסמה המערכת עוצרת במסך "אימות דו-שלבי": בפעם הראשונה מגדירים את האפליקציה (QR או מפתח ידני), ואחר כך בכל כניסה
  מקלידים קוד. **האכיפה במסד**: `fin_has_role` מחזירה אמת רק כשהטוקן ברמת `aal2`, ולכן גם קריאה ישירה ל-API עם טוקן
  אחרי סיסמה בלבד מקבלת טבלאות ריקות ו-403 (`MFA_REQUIRED`). הסוד של ה-TOTP נשמר בשרת ההתחברות של Supabase, לא אצלנו.
- **חיבורים (sessions)**: `fin_has_role` בודקת גם שהחיבור עדיין קיים ב-`auth.sessions`. "יציאה מכל המכשירים" (הגדרות › האבטחה שלי),
  "ניתוק מכל המכשירים" של מנהל, וחסימה מוחקים את החיבורים, והגישה למסד נעצרת מיד ולא רק כשהטוקן פג.
- **חסימה**: במקום "השבתה" בלבד. השרת (`member-block`) חוסם את הכניסה אצל ספק ההתחברות (`ban_duration`), מסמן `active=false`,
  מוחק את החיבורים ורושם ביומן. ההיסטוריה של המשתמש נשמרת. מנהל לא חוסם את עצמו; עובד לא חוסם אף אחד.
- **ניתוק אחרי חוסר פעילות**: `fin_settings.idle_minutes` (ברירת מחדל 30). דקה לפני כן מופיע פס אזהרה; כל נגיעה מאפסת.
- **יומן כניסות** (`fin_login_events`, נכתב רק מהשרת): כניסה, ניסיון שנכשל (מייל וזמן בלבד, אף פעם לא סיסמה), הגדרת אימות,
  קוד שגוי, יציאה מכל המכשירים, חסימה, ניתוק אחרי חוסר פעילות. כניסה ממכשיר חדש (מזהה בדפדפן) שולחת מייל למשתמש.
  לשונית "כניסות ואבטחה" במסך המשתמשים: כניסות ב-24 שעות, כשלונות, מחוברים עכשיו, כמה עם אימות דו-שלבי, חסומים, מי לא נכנס 30 יום.
- **מסך הכניסה**: הצגת סיסמה, "שכחתי את הסיסמה" (הודעה אחידה בין כתובת קיימת ללא קיימת), הודעות ברורות לחשבון חסום ולהגבלת ניסיונות,
  ובחירת סיסמה חדשה מהקישור במייל (10 תווים לפחות; סיסמה שמוכרת מדליפות נדחית ע״י ספק ההתחברות).
- **לא נבנה**: אימות מחדש לפני פעולה רגישה; תפקיד "צפייה בלבד" ותפקידים מותאמים; הרשאה לפי פעולה (View/Edit/Export…) מעבר לתפקיד;
  מכשירים "מאושרים" (זכירת מכשיר שמדלגת על הקוד); סריקת וירוסים לקבצים; תת-דומיין `finance.` (ראו ROADMAP.md).

## כניסה, הגדרות לפי חברה ומסמך מלא (גרסה 13)

- **חיבור ראשון**: אחרי הכניסה הראשונה המערכת מציעה לחבר את תיבת המייל שאיתה נכנסו (`fin_finish_onboarding`).

- **תפריט פרופיל** בלי חיובים ומנויים (מערכת פנימית), חלון העלאה וסקירה משופרת.

## אימות דו-שלבי: אין גישה לאפליקציה

הקוד לא נשלח במייל או ב-SMS; הוא נוצר באפליקציית האימות בטלפון ומתחלף כל 30 שניות.
- **משתמש איבד את האפליקציה:** מנהל מערכת › הארגון ומשתמשים › הפעולות ליד השם › "איפוס אימות דו-שלבי". האפליקציה הקיימת מפסיקה לעבוד, החיבורים מתנתקים, ובכניסה הבאה מגדירים מחדש (נרשם ביומן הכניסות ובהיסטוריה).
- **מנהל יחיד שאיבד את האפליקציה** (אין מי שיאפס): Supabase › Authentication › Users › המשתמש › למחוק את ה-MFA factor. או ב-SQL Editor:
  `delete from auth.mfa_factors where user_id = (select id from auth.users where email = 'המייל@שלך');`
