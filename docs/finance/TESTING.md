# בדיקת קצה-לקצה · KURKOOS FINANCE AI

הבדיקה מרימה עותק מקומי של Supabase ומריצה את המערכת האמיתית מולו, בדפדפן Chromium (Playwright):
מסד Postgres עם כל ההרשאות והטריגרים, Supabase Auth (GoTrue), Supabase Storage, PostgREST, קוד השרת ללא שינוי, והממשק.

**מה מדומה:** Google OAuth + Gmail API, ‏Google Drive, ‏Dropbox, ‏Green API (WhatsApp), מקבל webhook, ‏Claude, ‏Resend ושרת SMTP (scripts/finance-e2e/fakes.mjs). הם מדברים באותו פורמט HTTP של השירותים האמיתיים.
Claude המדומה עונה מטבלה לפי טביעת הקובץ, ולכן הבדיקה בודקת את כל מה שמסביב ל-AI ולא את איכות הקריאה שלו. את זה בודקים עם מפתח אמיתי (למטה).

## מה עוד צריך לבדוק עם חשבונות אמיתיים

- T1 עד T3 מול Gmail אמיתי: דורש GOOGLE_CLIENT_ID/SECRET וחשבון Workspace. אותו קוד, רק הכתובות משתנות.
- איכות הקריאה של Claude: להעלות 20 חשבוניות אמיתיות מגוונות (עברית, אנגלית, סרוקות, צילום טלפון) ולהשוות לשדות. הסכמה והפרומפט ב-server/finance/extract.js.
- Outlook / 365: הקוד קיים (providers/outlook.js) ולא נבדק מול Microsoft.
- WhatsApp (Green API), Google Drive, Dropbox ו-webhook: נבדקו מול שרתים מדומים באותו פורמט. לפני שימוש: מופע Green API אמיתי, אפליקציות OAuth, ושליחה אחת של מסמך אמיתי לכל ערוץ.
